# DECISIONS — ME Group

Format: ID · Decision · Reason · Status (Proposed / Accepted / Open)

- **D-01 · Next.js App Router + TypeScript strict, greenfield.** Repo is empty; brief mandates it. Server Components default for performance/SEO. *Proposed.*
- **D-02 · Vanilla CSS with tokens + CSS Modules, no Tailwind.** Brief calls for a systematic token system; vanilla CSS keeps it maintainable. Hex/rgb live only in the token file. *(Revised: no custom lint rule in Phase 1; discipline via review.)* *Proposed.*
- **D-03 · Brand red source of truth.** Brief says ~`#F51B23`; logo PNG samples ≈ `#ED1C24`. Use logo value as token `--color-brand-red` so UI matches the logo. Needs client/brand-guide confirmation. *Open.*
- **D-04 · Typography: Barlow Condensed / Barlow / IBM Plex Mono — initial hypothesis, not frozen.** (Superseded by D-15.) *Approved as hypothesis.*
- **D-05 · Arabic/RTL readiness without building Arabic.** Logical CSS properties, `dir` handling, content model with locale-ready shape; `[locale]` route group added only when approved; IBM Plex Sans Arabic as candidate. *Proposed.*
- **D-06 · No animation library in v1.** CSS transitions, SVG stroke draw, `clip-path`, IntersectionObserver are sufficient for the motion concept. Revisit only with a specific, measured need. *Proposed.*
- **D-07 · Brief vs. house-style reconciliation (revised).** Earlier flat-only/calm-minimal constraints are relaxed per D-14. Target is PREMIUM · INDUSTRIAL · TECHNICAL · CINEMATIC · PRECISE · CONFIDENT; cinematic comes from scale, composition, photography and purposeful motion. Decorative effects remain off by default. *Accepted.*
- **D-08 · Content gating via `status` + feature flags + build guard.** Prevents accidental publication of unverified facts; `responseTime` typed `never`. *Proposed.*
- **D-09 · Forms: Server Actions + Zod + pluggable `LeadSink`.** No integration hardcoded; spam strategy (honeypot + rate limit, CAPTCHA TBD) and upload storage deferred until infra confirmed. *Open.*
- **D-10 · Do not assert Egypt/Alexandria coverage.** Keywords are SEO targets only; location copy/schema only after client confirms. *Accepted.*
- **D-11 · Logo handling (revised).** Official supplied assets are used unmodified; never redrawn, traced or reinterpreted (D-19). Request an official vector/transparent master from the client; until then use PNG via `next/image`. *Open (asset request).*
- **D-12 · Build components when needed, not upfront.** Visual Lab precedes page production (D-16). *Accepted.*
- **D-13 · Tablet/mobile re-composition, sticky mobile support bar.** Fastest path to support within seconds on small screens. *Proposed.*
- **D-14 · Creative rules relaxed (revision 2).** "No gradients" becomes a strong default: avoid decorative gradients, glow, glassmorphism and trendy effects, but a justified gradient/overlay/brand treatment is allowed when it materially improves a composition (named token + justification). The "red <= 5% of viewport" rule is removed: ME Red stays controlled and intentional (CTAs, interaction states, technical indicators, important brand moments); large red surfaces allowed exceptionally for deliberate high-impact moments. Identity: PREMIUM, INDUSTRIAL, TECHNICAL, CINEMATIC, PRECISE, CONFIDENT; minimalism is a tool, not the identity. *Accepted.*
- **D-15 · Typography gate.** Barlow Condensed + Barlow + IBM Plex Mono is the initial hypothesis. Phase 2 produces a specimen (KEEPING VESSELS MOVING., MARINE ENGINEERING, headings, body, navigation, buttons, technical labels, data/equipment labels) shown next to the real ME logo. Typography is frozen only after visual approval. Fonts are loaded in one module so swapping stays cheap until then. *Accepted.*
- **D-16 · Phase order revised.** 0 Documentation, 1 Foundation, 2 Visual Lab / Design System, 3 Homepage, 4 Conversion System / Forms, 5 Services & Capabilities, 6 Company / Projects / Insights, 7 Motion/Responsive/Accessibility/Performance polish, 8 SEO/Analytics/Integrations/Launch. Homepage is validated before deep forms investment (zod and Server Actions move to Phase 4). *Accepted.*
- **D-17 · Lean Phase 1.** Priorities: foundation, tokens, typography, responsive grid, app shell, navigation, brand assets, basic content architecture, accessibility foundation. No custom lint rules, internal tooling or speculative abstractions. (Content-model additions such as MediaSlot are introduced here as small typed modules; CONTENT_MODEL.md will be updated then.) *Accepted.*
- **D-18 · Photography is a first-class layer; temporary media is clearly dev media.** Replaceable MediaSlots for vessel exterior, engine room, engineer at work, generator, switchboard, control panel/PLC, pneumatic equipment, pump/machinery, technical inspection, spare parts. Every temporary asset carries provenance "development-media" in the content layer, shows a dev marker in development, is never presented as ME Group work, and is blocked from production builds. *Accepted.*
- **D-19 · Logo integrity.** The supplied official logo assets are used as-is and never redrawn or reinterpreted. A separate "frame-motif" (CSS/SVG geometry inspired by the outer ME frame) may be used for masks, frames and motion but never replaces or modifies the logo. *Accepted.*
- **D-20 · Visual Lab is a real identity-in-context route, not Storybook.** /lab (dev, noindex) covers typography specimen, palette/surfaces, CTA hierarchy, navigation behavior, technical markers, photography treatments, frame-inspired masks, schematic language, motion experiments (line drawing, controlled reveal, technical scan, image mask transition) and at least 2 hero concepts. The full homepage is not built in Phase 2. *Accepted.*
- **D-21 · Visual-quality guardrails.** Avoid SaaS-dashboard look, generic corporate minimalism, repetitive card grids, excessive boxed sections, generic marine-blue aesthetics and template layouts; prefer asymmetry, scale, editorial composition, engineering graphics, photography and controlled motion. *Accepted.*
- **D-22 · Phase 1 implementation deviations.** (a) Full desktop navigation + mega menu starts at 1280px (not 1024px): with 6 items plus Rapid Support and the full CTA, 1024-1279 does not fit; those widths use the drawer + sticky support bar. (b) Mobile nav uses a native modal dialog element (focus trap, Escape and focus return provided by the browser). (c) Mega-menu open state is bound to the pathname so navigation closes it without an effect. (d) No Rule primitive was created; a global hr style suffices. (e) No web manifest in Phase 1; the supplied ME icon is served via the Next icon.png convention. Manifest colors cannot use CSS variables, so it is deferred. (f) Footer service-group links use /services#group anchors; there are no group index routes. (g) Primary button uses brand red with white text; contrast is about 4.4:1 (slightly under 4.5:1 for small text) - to be resolved in the Phase 2 Visual Lab (D-03). *Accepted.*
- **D-23 · Additional supplied brand asset.** An official square ME icon (164x164) was added to the project and is stored unmodified as public/brand/me-group-icon.png (also used as the favicon). *Accepted.*
- **D-24 · Indexing safety.** noindex and a disallow-all robots.txt unless NEXT_PUBLIC_SITE_ENV=production. *Accepted.*
- **D-25 · Phase 1 verification pass.** Verified with an automated Edge (Playwright) run at 1920/1440/1280/1279/1024/768/767/390. Fixes: (a) the Services mega panel now sits inside the Services list item so it is next in tab order after the button; (b) the menu closes as soon as focus leaves the Services item; (c) the mega-panel intent link now meets the 44px target; (d) the mobile dialog focuses Close on open. Known and accepted: Tab past the last control of the native modal dialog moves to browser UI (native behavior, page content stays inert). Primary CTA contrast (white on #ed1c24) is 4.38:1; text is 14px/600 uppercase, which is NOT WCAG large text, so it fails AA by 0.12; left for Phase 2 (D-03). npm audit: 5 high, all dev-only transitive via eslint-config-next to braces; no fix exists. *Accepted.*
- **D-26 · Phase 2 Visual Approval & Phase 3 Homepage Architecture.** (a) Visual Direction approved: CINEMATIC PRECISION (Cinematic marine engineering + precision technical graphics + editorial composition). (b) Color & Accessibility: Action Red `--color-brand-red-action: #d9141b` (4.85:1 contrast, WCAG AA compliant on light surfaces) approved for text/button UI actions; Official Logo Red `#ed1c24` preserved untouched for brand marks. (c) Hero Film Architecture: Concept D hero implemented using native HTML5 video with `poster` fallback (`/images/dev/hero-video-poster.svg`), directional readability scrim, and `prefers-reduced-motion` compliance. (e) Omitted Sections: Sections 08 (Projects), 10 (Geographic Coverage), 12 (Clients/Certifications), 13 (Insights) intentionally omitted from production per strict no-unconfirmed-claims policy. *Accepted.*
- **D-27 · Phase 4 Conversion System & Forms Architecture.** (a) Four distinct conversion intents implemented: Technical Support (`/contact/technical-support`), Rapid Support (`/contact/rapid-support`), Spare Parts (`/contact/spare-parts`), and General Enquiry (`/contact`). (b) Technical Support flow uses structured 5-step progressive disclosure (Vessel -> System -> Problem Scope -> Attachments -> Contact). (c) Spare Parts flow supports dual-path intake: Path A (Known OEM Part Number) and Path B (Nameplate/Machinery Photo Identification). (d) Rapid Support uses ultra-streamlined emergency triage with immediate phone escalation. (e) Zero-overhead custom validation layer used without extra dependencies, keeping bundle lean and fast. (f) Server Actions with explicit development/mock boundary logging intake data cleanly without fabricating CRM tracking numbers. *Accepted.*
- **D-28 · Phase 5 Services & Capabilities Architecture.** (a) Route Architecture: Clean scalable top-level routes implemented for all 7 confirmed disciplines (`/services`, `/services/mechanical`, `/services/electrical`, `/services/automation`, `/services/pneumatic`, `/services/repair-maintenance`, `/services/vessel-support`, `/services/spare-parts`) alongside a technical navigation matrix (`/capabilities`). Legacy 2-level Phase 1 URLs permanently redirected via `next.config.ts`. (b) Taxonomy Architecture: Organized into three operational tiers: Group A (Engineering Systems: Mechanical, Electrical, Automation, Pneumatics), Group B (Repair & Maintenance: 5-Stage Lifecycle + Preventive vs Corrective matrix), and Group C (Vessel Support: Technical Supplies, Consumables, Potable Water, Provisions, and Spare Parts). (c) Phase 4 Conversion Integration: All service CTAs connect directly to `/contact/technical-support?system={discipline}`, `/contact/spare-parts`, and `/contact/rapid-support` with functional preselection. (d) Visual Differentiation: Shared modular component library (`ServiceHero`, `ServiceScopeSection`, `ServiceEquipmentSection`, `ServiceProcessSection`, `ServiceCrossDisciplines`, `ServiceProblemScenarios`, `ServiceConversionCta`) styled with discipline-specific visual motifs while strictly adhering to CSS variables from `:root` and flat colors (no gradients). (e) Factual Integrity: Zero invented claims, certifications, response-time guarantees, or voltage/pressure ratings. *Accepted.*
- **D-29 · Phase 6 Company, Projects & Insights Architecture.** (a) Company Routes: Implemented confirmed institutional pages (`/company`, `/company/about`, `/company/approach`, `/company/quality-safety`). (b) Quality & Safety Integrity: Stance remains strictly conservative and truthful—zero fake ISO/IACS badges or fabricated HSE statistics; focus placed on confirmed technical protocols (safe isolation, precision measurement, live testing, environmental containment). (c) Reconciled Engineering Approach: Unified the 5-stage lifecycle (*Inspect & Identify → Diagnose → Repair & Intervene → Test & Verify → Commission & Support*). (d) Projects & Case Studies Model: Typed `CaseStudy` model created with support for partial/confidential client/vessel records; public `/projects` route is strictly feature-gated behind `features.projects` (returns 404 while unconfirmed, avoiding empty or fake placeholder cards). (e) Insights & Technical Publications Model: Typed `Article` model created; future content strategy topics documented in code without publishing fake articles; `/insights` route is feature-gated behind `features.insights`. (f) Trust Signals: `CertificationItem`, `ClientLogoItem`, and `CompanyMetricItem` typed and guarded behind feature flags (`features.certifications`, `features.clients`, `features.metrics`). *Accepted.*
- **D-30 · Phase 7 Final Experience Polish.** (a) Content Integrity Audit: Strict generalization applied to remove overly specific procedural claims (e.g. generalized "zero-energy isolation", "calibrated measuring instruments", "live operational testing under load before sailing", and specific voltage/pressure figures to confirmed broader terminology). (b) CSS Architecture & Tokens: Added centralized motion tokens (`--dur-standard: 240ms`, `--ease-mechanical: cubic-bezier(0.16, 1, 0.3, 1)`); confirmed 100% adherence to `:root` CSS variables and flat colors (zero gradients). (c) Form UX Refinements: Rapid Support form streamlined to "Current Port / Location" (no mandatory geographic coordinates); File upload zone conservatively specifies standard image and document formats (PDF, JPG, PNG, WEBP, DOCX) without unbacked DWG parser guarantees. (e) Zero Gated Leakage & SEO: Verified sitemap, robots, headers, and meta contain zero unconfirmed or gated items. *Accepted.*
- **D-32 · Phase 8 Production Integration & Launch Readiness.** (a) Final Truth Gate: Re-audited and generalized all remaining over-specific or procedural claims across quality & safety, services, and capabilities (e.g., replaced "Lockout Protocols" and "Fluid Containment" with confirmed broader engineering terms: "Safety-Conscious Technical Work", "Technical Inspection & Diagnostics", "Testing & Verification", "Professional Maintenance Practices"; standardized generator/compressor/breaker vocabulary). (e) Typed Environment Layer: Created `.env.example` and `src/config/env.ts` separating public config from server secrets. (f) Zero-PII Analytics Layer: Created `src/lib/analytics.ts` preserving semantic conversion events without transmitting sensitive vessel/personal data. (g) Production SEO & Structured Data: Verified canonical URLs, valid Open Graph / Twitter tags, and confirmed-only Organization JSON-LD; robots.txt and sitemap.xml strictly disallow and exclude `/lab` and unconfirmed routes.
